# 코드를 직접 작성하지 않은지 1년, IDE를 쓰지 않은지 2개월 소감

IntelliJ를 1년짜리로 구독해 두었는데 지금은 Orca 하나만 쓴다. 코드는 1년쯤 전부터 직접 작성하지 않았고 IDE는 메모리를 너무 많이 잡아먹어서 8월 초에 Orca를 설치하고 8월 중순부터는 IDE를 거의 쓰지 않았다.

1년 전쯤 전 직장에서 Copilot이나 JetBrains Junie, Claude Code 같은 도구를 이것저것 쓰기 시작했던 것 같은데 AI를 정말 깊게 쓰게 된 건 4월에 지금 회사로 옮기고 나서부터다.

생존을 위해서였다고 해야 할까. 새 회사에서는 컨텍스트도 없고 의존할 곳도 없으니 AI를 적극 활용해서 빠르게 온보딩했다.

## Orca

Orca는 코딩 에이전트 여러 개를 병렬로 돌리는 앱이고 ADE라고도 불린다. 지금은 하루에 프로젝트 3-5개를 오가면서 세션을 동시에 3-4개 돌리는 편이다.

세션 기록을 보면 실제로 말을 주고받던 세션은 8월에 평균 2개 남짓이었는데 9월에는 3개 안팎으로 늘었다.

IDE는 메모리 때문에 끊었는데 세션을 병렬로 계속 돌리다 보니 이쪽도 메모리를 많이 차지하기는 한다. 

## 가드레일

요즘은 가드레일을 보강하고 개선하는 데 시간을 많이 쓰는 것 같다. 코드 품질을 유지하고 테스트를 보강하고 지침이 지켜지도록 검증 게이트를 추가한다.

## 느낀점

개발하는 손맛 같은 건 많이 없어진 것 같다. 예전에는 TDD로 개발하면서 red와 green을 보고 리팩터링하고 실제로 애플리케이션을 띄워서 확인하는 과정이 있었다.

실패하는 테스트를 만들고 성공시키면서 성취감 같은 것도 있었고 만드는 재미도 느꼈던 것 같다.

예전에는 동료와 페어 프로그래밍을 하면서 처음 생각보다 더 좋은 방법으로 구현하기도 했다.

AI가 나온 뒤로는 그런 페어 프로그래밍도 하기가 어려웠다. 지금은 프롬프트 작성하고 결과를 지켜보는 거라서 좀 안 맞는거같다.

그러다 보니 노하우를 전수하기도 어렵고 좀 비효율적이다. 그래서 나중에는 페어를 하지 않고 팀원에게 비동기로 물어보면서 진행 방식을 듣고 피드백을 주는 식으로 바뀌었던 것 같다.

그리고 AI를 여러 개 쓰다 보니 결론이 뭐냐고 묻는 경우가 많아졌다. 세션 여러 개를 오가면서 AI가 한 대답을 전부 읽지 않고 결론부터 찾게 되는데 이미 결론을 말한 걸 다시 되묻는 경우도 많다.

윗직급으로 갈수록 관리할 사람이 많아져서 결론을 묻게 되는 것과 똑같은거같다.  AI 에이전트를 직원으로 둔다는 게 이런 것 같다.

병렬로 AI를 쓰면서 일은 더 많이 하게 됐고 더 바빠진 것 같기도 하다. 그렇다고 IDE로 한땀한땀 개발하던 시절로는 답답해서 못 돌아간다. 생산성 차이가 너무 크다고 해야 할까.

AI를 활용하면서부터 개발 쪽에서는 기술 스택이나 직무라는 것이 좀 옅어진 것 같다. 예전 같으면 백엔드 개발자라고 백엔드 개발만 했겠지만 지금은 언어나 영역에 관계없이 회사의 문제를 푸는 일을 한다.
